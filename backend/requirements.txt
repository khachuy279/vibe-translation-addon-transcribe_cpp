# ---------------------------------------------------------------- llama.cpp (dịch GGUF)
# PHÂN TÁCH BINDING ↔ DLL — lý do KHÔNG phải build từ source nữa:
#   * Wheel CUDA dựng sẵn của abetlen chỉ chứa kernel tới `sm_90` ⇒ GPU Blackwell (sm_120) phải
#     chạy qua **PTX JIT** (đo được: decode 48,3 tok/s, nạp model 4,33 s), và nhiều bản
#     0.3.25–0.3.35 còn build kèm **AVX-512** ⇒ nổ `0xc000001d` trên CPU không có AVX-512.
#   * Binding Python (ctypes) thì giống nhau giữa mọi wheel cùng phiên bản, nên ta chỉ cần LẤY
#     BINDING từ wheel CPU 7 MB, rồi trỏ DLL sang bản CUDA trong repo:
#         LLAMA_CPP_LIB_PATH=<repo>/backend/bin/llama
#     (`backend/utils/cuda.py::setup_llama_cpp_dll_path` đặt env này; `setup_cuda_dll_paths()`
#      gọi nó tự động nên mọi caller cũ không phải đổi gì.)
#   * Ưu điểm: DLL CPU trong wheel KHÔNG bao giờ được nạp ⇒ vô hiệu hoàn toàn cả lỗi AVX-512
#     lẫn PTX JIT. Đo lại qua đúng đường đi của app: decode 67,6 tok/s · prefill 2.710 tok/s ·
#     nạp model 2,26 s · `offloaded 33/33 layers to GPU` · `ARCHS = 1200`.
#   * Muốn dựng lại DLL CUDA: `scratch\build_llama_cpp_cuda_blackwell.bat`, rồi chép
#     `llama.dll` + `ggml*.dll` + `mtmd.dll` từ `llama_cpp\lib\` vào `backend/bin/llama/`.
#   * ⚠️ DLL llama.cpp PHẢI ở thư mục RIÊNG, không để chung `backend/bin/`: cả hai bên đều có
#     `ggml.dll`/`ggml-base.dll`/`ggml-cpu.dll`/`ggml-cuda.dll` nhưng là hai bản ggml khác nhau,
#     Windows phân giải theo tên module nên để chung sẽ chết với `0xc0000139`.
